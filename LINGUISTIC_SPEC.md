# Stage 5D linguistic and literary contracts

VECTOR remains offline. Acquisition is a separate developer operation, never an
application network permission. Imported sources are inert, exact original bytes.
This implementation separates a curriculum, attested linguistic records, mechanical
text observations, subjective interpretations, model competence and future training.

Languages use extensible identifiers, explicit scripts/varieties and coverage state.
The initial 40 modern + three historical entries are curriculum targets, not
proficiency. English domains list intended study areas. Latin/Greek/Hebrew analyses
separate original text, transliteration, morphology, gloss, translation, commentary
and variants. No unattested lexicon, etymology or inflection is generated as fact.

Registered literary_editions records identify digital editions, work grouping keys,
source URLs, authors/translators, language, publication metadata (unknown print dates
remain null), rights evidence/jurisdiction, exact original hash and import status.
Rights approval is explicit and cannot be granted by a model. Provider assertions
are not a global legal warranty. U.S.-only acquisition was selected by the user.
Distinct editions/submissions retain events; equivalent byte content is deduplicated
by existing storage. Work grouping is conservative author/title grouping, not a
scholarly authority resolution claim. Translations/volumes use explicit links.

Offline packages contain manifest.ndjson and objects/SHA256 files. Each bounded
manifest line is strict JSON. Paths derive only from verified hashes; archive files,
symlinks, traversal, executable formats and unknown rights are rejected. Files are
verified before acknowledgement. Batch import is resumable by byte cursor; a failed
item never destroys an acknowledged original. No total work count cap exists.

Derived passage units retain exact character offsets, ordering, structural labels,
original hashes and processing versions. Paragraphs/stanzas keep line endings;
long paragraphs split into labelled continuations rather than discarded content.
Sentence and heading recognition are bounded heuristics, not a syntactic parser.
Contentless FTS postings are rebuildable; results reread and verify original spans.
Processing is bounded and checkpointed, complete unchanged editions are not rerun.
Large unsupported extraction retains originals with an explicit deferred status.

Linguistic nodes represent phonemes/morphemes/lemmas/forms/categories/constructions/
senses/definitions/idioms/figures/etymology/cognates/borrowings/translations/semantic
relations/history/literary forms/rhetoric/prosody. Records carry source attestations,
method, uncertainty and version. Relationships distinguish exact/approximate/related/
etymological/borrowing/uncertain interpretations and require explicit approval.
Attestations certify what a source says, not independent truth. Interpretations
remain pending until reviewed and stay labelled interpretations after approval.

Mechanical analysis reports exact text structure, vocabulary/repetition and literal
orthographic patterns. Rhyme/meter/theme/symbolism/irony and historical morphological
competence are not certified by spelling or model text. Independent tests and real
corpus measurements must distinguish those boundaries. No neural training is run.

All records and source assets participate in existing registered portable state;
derived indexes have exact schema, safe rebuild and corruption checks. Desktop
library controls share the fixed offline service boundary. Existing project/source
links and strict response citation checks are reused, not duplicated.

Each completed work also has a registered literary_analyses record: original-body
bounds, literal line/block/token counts, bounded casefolded-form candidates with
exact source spans, and a sampled Unicode script inventory. These are mechanical
observations, not learned senses or semantic understanding. PG headers/licenses
remain preserved but are excluded from body statistics. Import cursors bind to the
exact manifest identity; changed packages require a safe idempotent restart.
